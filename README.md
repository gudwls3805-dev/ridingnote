# 라이딩노트

출발지와 조건을 입력하면 AI가 이륜차로 달릴 수 있는 투어링 코스 2~3개를 추천하는 웹 서비스입니다.

- 배포 URL: https://ridingnote.vercel.app
- GitHub: https://github.com/gudwls3805-dev/ridingnote

## 왜 만들었나

주말에 바이크를 타러 나가려면 "어디로 갈지"부터 정해야 합니다. 아는 코스가 적은 1~3년 차 라이더는 이 단계에서 시간을 많이 씁니다.

그냥 길찾기 앱이나 AI에게 물어보면 되지 않나 싶지만, 한국에서 이륜차는 고속도로와 자동차전용도로를 달릴 수 없습니다. 조건 없이 물으면 이 도로가 섞인 경로가 나올 수 있습니다.

그래서 배기량과 시간, 선호하는 길을 입력받고 "국도·지방도만 사용"이라는 조건을 붙여 코스를 추천받는 서비스를 만들었습니다.

## 사용 방법

1. **코스 추천** 섹션에서 조건을 입력합니다.

   | 항목 | 선택지 | 필수 |
   | --- | --- | --- |
   | 출발 지역 | 자유 입력, 30자 이내 (예: 서울 강동구) | 필수 |
   | 라이딩 시간 | 반나절 / 하루 / 1박 2일 | 기본값 하루 |
   | 선호 스타일 | 와인딩 / 해안도로 / 산길·고개 / 카페 투어 | 기본값 와인딩 |
   | 배기량 | 125cc 이하 / 중배기량 / 대배기량 | 기본값 중배기량 |
   | 추가 요청 | 자유 입력, 200자 이내 | 선택 |

2. **코스 추천받기**를 누르면 코스 카드 2~3개가 나옵니다. 카드에는 경유지, 예상 소요 시간, 대략적인 거리, 휴식 포인트, 주의사항이 들어갑니다.
3. 경유지 이름을 누르면 네이버지도 검색 결과가 새 탭으로 열립니다.

페이지는 한 장이고, 상단 메뉴(홈 / 코스 추천 / 투어 준비 / FAQ)를 누르면 해당 섹션으로 이동합니다. 768px보다 좁은 화면에서는 메뉴가 햄버거 버튼으로 접힙니다.

## 실행 방법

### 로컬에서 실행

```bash
npm i -g vercel        # Vercel CLI 설치 (처음 한 번)
cp .env.example .env   # .env를 열어 GEMINI_API_KEY 값 입력
vercel dev             # http://localhost:3000
```

`index.html`을 더블클릭해서 열면 `/api/recommend` 함수가 실행되지 않아 AI 기능이 동작하지 않습니다. 반드시 `vercel dev`로 실행해야 합니다.

### 배포

1. GitHub 저장소를 Vercel에서 Import합니다.
2. Application Preset을 **Other**로 선택합니다.
3. Environment Variables에 `GEMINI_API_KEY`를 추가하고 Deploy합니다.
4. 이후에는 `git push`만 하면 자동으로 다시 배포됩니다.

Preset을 Other로 고른 이유: Vercel이 `requirements.txt`를 보고 Python 프리셋을 자동으로 고르는데, 이 프리셋은 프로젝트 전체를 하나의 Python 앱으로 보고 진입 파일을 찾습니다. 이 프로젝트는 정적 화면(`index.html`)과 함수(`api/recommend.py`)가 나뉜 구조라서 Other가 맞습니다. 설정 화면에 "Possible configuration mismatch" 경고가 뜨지만 배포와 함수 실행에는 문제가 없었습니다.

### 환경 변수

| 이름 | 필수 | 설명 |
| --- | --- | --- |
| `GEMINI_API_KEY` | 필수 | Google AI Studio에서 발급한 Gemini API 키 |
| `GEMINI_MODEL` | 선택 | 사용할 모델 이름. 없으면 `gemini-3.8-flash` |

환경 변수는 배포할 때 읽힙니다. 값을 바꾼 뒤에는 Deployments에서 **Redeploy**해야 적용됩니다.

키는 코드, README, 스크린샷에 넣지 않습니다. `.env`는 `.gitignore`에 들어 있어 GitHub에 올라가지 않습니다.

## 구조

```
ridingnote/
├── index.html          # 화면 구조 (4개 섹션)
├── css/style.css       # 스타일, 반응형 (768px, 1024px 기준)
├── js/app.js           # 메뉴, 입력 검사, fetch 호출, 결과 표시, 실패 안내
├── api/recommend.py    # POST /api/recommend → 입력 재검증 → Gemini 호출
├── images/
├── requirements.txt    # openai
├── vercel.json         # 함수 최대 실행 시간 60초
├── .env.example        # 환경 변수 예시 (실제 키 없음)
└── .gitignore          # .env 제외
```

### 요청 흐름

1. `js/app.js`가 폼 입력을 검사합니다.
2. `fetch('/api/recommend', { method: 'POST' })`로 조건을 JSON으로 보냅니다.
3. `api/recommend.py`가 입력을 한 번 더 검증하고, 환경 변수의 키로 Gemini를 호출합니다.
4. Gemini가 돌려준 JSON을 정리해서 응답하고, 프론트가 코스 카드로 그립니다.

키는 서버 함수 안에서만 쓰이므로 브라우저의 개발자 도구에는 나타나지 않습니다.

## 핵심 결정

### 기술 스택

- **HTML/CSS/JavaScript (프레임워크 없음), Vercel Serverless Functions (Python):** 과제 지정입니다.
- **AI: Google Gemini API.** 처음부터 Gemini를 고른 것이 아니라, 아래 과정을 거쳐 바뀌었습니다.

### AI API를 바꾼 과정

| 단계 | 확인한 것 | 판단 |
| --- | --- | --- |
| 1 | 교육 과정에서 받은 키로 호출하자 화면에 "서버 설정에 문제가 있어요"가 표시됨 | 키가 없거나 거절된 경우에만 나오는 메시지라 키 문제로 범위를 좁힘 |
| 2 | 응답에 원인 코드(`missing_key` / `invalid_key`)와 서버 로그를 추가해 다시 배포 | 화면만으로는 두 경우를 구분할 수 없었기 때문 |
| 3 | Vercel Logs에서 `api.openai.com ... 401 Unauthorized` 확인 | 키는 전달됐지만 OpenAI가 거절함 |
| 4 | 키가 `sk-cody-live-`로 시작하고, 콘솔의 "마지막 사용"이 비어 있음 | 이 키는 교육 과정 전용 서버(`copa.codyssey.kr`)에서만 쓰는 키. 요청이 엉뚱한 서버로 가고 있었음 |
| 5 | Gemini API로 전환 | 직접 발급하고 관리할 수 있는 키로 바꿈 |

Gemini는 OpenAI와 같은 형식으로 호출할 수 있는 주소(`https://generativelanguage.googleapis.com/v1beta/openai/`)를 제공합니다. 그래서 `openai` 파이썬 패키지와 요청 코드는 그대로 두고, `base_url`과 모델 이름만 바꿨습니다.

기본 모델 `gemini-3.8-flash`는 Gemini 공식 OpenAI 호환 문서의 예시에 쓰인 모델입니다. 다른 모델을 쓰려면 코드를 고치지 않고 `GEMINI_MODEL` 환경 변수만 바꾸면 됩니다.

### 정한 값

| 값 | 이유 |
| --- | --- |
| 서버의 AI 호출 제한 25초, 프론트 요청 중단 30초 | 서버가 먼저 끝나야 서버가 만든 안내 메시지가 사용자에게 전달됩니다. 프론트가 먼저 끊으면 원인을 알 수 없는 메시지만 남습니다. |
| 자동 재시도 0회 | 실패할 때마다 다시 호출하면 대기 시간과 사용량이 늘어납니다. 대신 사용자에게 다시 시도하라고 안내합니다. |
| 추가 요청 200자, 출발 지역 30자 | 지역명과 짧은 요청에는 충분하고, 긴 입력이 그대로 AI에 들어가는 것을 막습니다. 과제의 "200자 이상 긴 입력" 테스트 기준에도 맞췄습니다. |
| 8초 후 대기 안내 | 버튼을 누르고 반응이 없으면 멈춘 것처럼 보입니다. 결과가 나오기 전에 "처리 중"임을 한 번 알리기 위해 넣었습니다. 8초라는 숫자 자체는 실측 근거 없이 정한 값입니다. |
| 코스 2~3개 | 1개는 비교가 안 되고, 너무 많으면 응답이 길어지고 화면이 길어집니다. 정확한 상한은 임의로 정했습니다. |

## 예외 처리

과제 기준인 빈 입력, API 오류, 지연을 모두 다룹니다. 아래는 모두 구현되어 있습니다.

| 상황 | 감지 위치 | 사용자에게 보이는 안내 |
| --- | --- | --- |
| 출발 지역 빈칸 | 프론트(요청 전), 서버(400) | 출발 지역을 입력해 주세요. |
| 추가 요청 200자 초과 | 프론트, 서버(400) | 추가 요청은 200자까지 입력할 수 있어요. |
| 키 없음 / 키 거절 | 서버(500) | 서버 설정에 문제가 있어요. 관리자에게 알려 주세요. |
| 사용량 초과 | 서버(429) | 요청이 많아 잠시 쉬는 중이에요. 1분 뒤에 다시 시도해 주세요. |
| AI 서버 오류 | 서버(502) | 추천 서버가 응답하지 않아요. 잠시 후 다시 시도해 주세요. |
| AI 응답을 JSON으로 읽지 못함 | 서버(502) | 추천 결과를 읽지 못했어요. 다시 시도해 주세요. |
| 8초 이상 지연 | 프론트 | 코스를 고르는 중이에요. 조금만 기다려 주세요. |
| 30초 초과 | 프론트 | 응답이 너무 늦어요. 조건을 줄여서 다시 시도해 주세요. |
| 네트워크 끊김 | 프론트 | 네트워크 연결을 확인하고 다시 시도해 주세요. |

같이 구현한 보완책:

- 요청 중에는 버튼을 비활성화해 중복 호출을 막습니다.
- AI 결과는 `innerHTML`이 아니라 `textContent`로 넣습니다. 응답에 `<script>` 같은 문자열이 섞여도 실행되지 않고 글자로만 보입니다.
- 모델이 JSON 응답 옵션을 지원하지 않아 400을 주면, 옵션을 빼고 한 번 더 요청합니다.
- AI가 JSON을 코드 블록(```json)으로 감싸 보내도 `{`부터 `}`까지만 꺼내서 읽습니다.
- 키 오류 원인 코드(`missing_key`, `invalid_key`)를 응답에 포함하고, 로그에는 키 앞 7글자와 길이만 남깁니다. 전체 키는 출력하지 않습니다.

## 한계

아래는 구현하지 않은 부분입니다.

- **고속도로 제외는 보장되지 않습니다.** AI에게 지시만 할 뿐, 나온 경로를 실제로 검사하는 기능은 없습니다.
- **AI가 존재하지 않는 장소를 만들 수 있습니다.** 현재 대응은 결과 하단의 "출발 전 지도 앱으로 확인하세요" 안내와 경유지별 네이버지도 링크가 전부입니다.
- 거리와 소요 시간은 AI의 추정치입니다.
- 사용자별 호출 횟수 제한이 없습니다. 같은 사람이 계속 누르면 그만큼 사용량이 늘어납니다.
- 추천 결과를 저장하지 않습니다. 투어 준비 체크리스트도 새로고침하면 초기화됩니다.
- 날씨와 도로 통제 정보는 반영하지 않습니다.
