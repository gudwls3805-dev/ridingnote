# 라이딩노트 발표 대본

슬라이드 순서대로 말할 내용입니다. 발표자료.pdf와 함께 보세요.

## 01. 라이딩노트

오늘 발표할 서비스는 라이딩노트입니다. 출발지와 조건을 넣으면 AI가 바이크로 갈 수 있는 투어링 코스를 2~3개 추천해 주는 웹 서비스입니다. 배포 주소와 GitHub 주소는 화면 아래에 있습니다. 순서는 왜 만들었는지, 어떻게 동작하는지, 만들면서 부딪힌 문제와 해결, 그리고 한계 순으로 말씀드리겠습니다.

## 02. 주말 코스를 정하는 일, 생각보다 오래 걸린다

만든 이유는 두 가지 불편에서 시작했습니다. 첫째, 경력이 짧은 라이더는 아는 코스가 적어서 어디로 갈지 정하는 데 시간을 많이 씁니다. 둘째, 한국에서는 이륜차가 고속도로와 자동차전용도로를 달릴 수 없습니다. 그래서 그냥 길찾기나 AI에게 물으면 갈 수 없는 길이 섞여 나올 수 있습니다. 그래서 조건을 입력받고, 국도와 지방도만 쓰라는 조건을 붙여서 추천받는 서비스를 만들었습니다. 타겟은 아는 코스가 적은 1~3년 차 라이더입니다.

## 03. 한 페이지, 네 개의 섹션

과제 조건인 3개 이상의 섹션을 만족하도록 한 페이지에 네 개의 섹션을 두었습니다. 홈, 핵심 기능인 코스 추천, 투어 준비 체크리스트, FAQ입니다. 상단 메뉴는 앵커 링크로 해당 섹션으로 이동하고, 스크롤 위치에 따라 지금 보고 있는 메뉴가 강조됩니다. 반응형은 두 기준을 두었습니다. 768픽셀보다 좁으면 메뉴가 햄버거 버튼으로 접히고, 1024픽셀 이상이면 입력 폼과 결과가 좌우로 나란히 배치됩니다.

## 04. 조건 5개를 넣으면 코스 카드 2~3장이 나온다

핵심 기능은 코스 추천입니다. 입력은 다섯 가지입니다. 출발 지역만 필수이고, 나머지는 기본값이 있어서 출발 지역만 넣어도 바로 추천받을 수 있습니다. 출력은 코스 2~3개이고, 코스마다 경유지, 예상 시간, 거리, 휴식 포인트, 주의사항이 들어갑니다. 경유지를 누르면 네이버지도 검색이 새 탭으로 열려서 실제로 있는 곳인지 바로 확인할 수 있습니다. AI가 틀릴 수 있기 때문에 결과 아래에는 출발 전에 지도 앱으로 확인하라는 안내를 항상 붙였습니다.

## 05. 브라우저는 키 없이 우리 서버 함수만 부른다

구조입니다. 사용자가 폼을 제출하면 app.js가 먼저 입력을 검사하고, fetch로 /api/recommend에 POST 요청을 보냅니다. 이 주소는 Vercel 서버리스 함수인 recommend.py입니다. 함수는 입력을 한 번 더 검증하고, 프롬프트를 만들어 Gemini API를 호출합니다. 받은 JSON을 정리해서 돌려주면 화면이 카드로 그립니다. 핵심은 API 키 위치입니다. 키는 Vercel 환경 변수에만 있고, 서버 함수 안에서만 읽습니다. 그래서 브라우저 개발자 도구나 GitHub 코드에서는 키를 볼 수 없습니다. 프론트에서 직접 AI를 호출하면 키가 노출되기 때문에 이렇게 서버를 한 단계 거치게 했습니다.

## 06. 과제가 정한 것과 내가 고른 것

기술 스택입니다. 프론트엔드는 프레임워크 없이 HTML, CSS, 자바스크립트로 만들었고, 백엔드는 Vercel 서버리스 함수를 Python으로 작성했습니다. 이 둘과 배포 방식은 과제에서 지정한 것입니다. 제가 고른 것은 AI입니다. 처음에는 교육 과정 키로 OpenAI 방식을 썼는데, 뒤에서 설명할 401 오류 때문에 Gemini로 바꿨습니다. Gemini가 OpenAI와 같은 형식의 주소를 제공해서, openai 패키지와 요청 코드는 그대로 두고 주소와 모델 이름만 바꿀 수 있었습니다. 프론트에서는 fetch로 서버를 호출하고, AbortController로 30초가 지나면 요청을 끊고, IntersectionObserver로 스크롤 위치에 맞춰 메뉴를 강조했습니다.

## 07. AI에게 지킬 규칙 5개를 먼저 준다

AI에게는 시스템 프롬프트로 규칙 다섯 개를 먼저 줍니다. 가장 중요한 건 1번, 고속도로와 자동차전용도로를 빼라는 규칙입니다. 이 서비스를 만든 이유와 바로 연결됩니다. 2번은 배기량이 작으면 무리한 코스를 피하라는 것이고, 3번은 AI가 없는 가게 이름을 지어내는 문제를 줄이려고 넣었습니다. 그리고 응답을 정해진 JSON 형식으로만 받게 해서, 화면이 항상 같은 모양의 카드로 그려지게 했습니다. 다만 이건 지시일 뿐이라 AI가 100% 지킨다는 보장은 없습니다. 이 부분은 한계에서 다시 말씀드리겠습니다.

## 08. 과제 기준 3가지(빈 입력·API 오류·지연)를 모두 처리

과제에서는 실패 처리를 하나 이상 요구했는데, 빈 입력, API 오류, 지연 세 가지를 모두 처리했습니다. 빈 입력은 프론트에서 먼저 막아서 서버 요청 자체를 보내지 않고, 서버에서도 한 번 더 검사합니다. 프론트 검사는 개발자 도구로 우회할 수 있기 때문입니다. API 오류는 상태 코드별로 다른 안내를 보여 줍니다. 지연은 8초가 지나면 기다려 달라는 안내를, 30초가 지나면 요청을 끊고 다시 시도하라는 안내를 보여 줍니다. 추가로 요청 중에는 버튼을 비활성화해서 중복 호출을 막았고, AI 결과는 textContent로 넣어서 응답에 스크립트가 섞여 와도 실행되지 않게 했습니다.

## 09. 키는 맞는데 요청이 엉뚱한 서버로 가고 있었다

가장 오래 걸린 문제입니다. 배포 후 추천받기를 누르면 서버 설정에 문제가 있다는 안내가 나왔습니다. 이 문구는 키가 없거나 거절될 때만 나오는데, 화면만으로는 둘 중 어느 쪽인지 알 수 없었습니다. 그래서 응답에 원인 코드를 넣고, 서버 로그를 남기도록 코드를 고쳐서 다시 배포했습니다. Vercel 로그를 보니 api.openai.com으로 간 요청이 401 Unauthorized를 받고 있었습니다. 키는 전달됐는데 OpenAI가 거절한 겁니다. 확인해 보니 교육 과정에서 받은 키는 sk-cody-live로 시작하는 코디세이 전용 서버 키였고, 콘솔의 마지막 사용 기록도 비어 있었습니다. 요청이 코디세이 서버에 한 번도 도착하지 않았다는 뜻입니다. 최종적으로 Gemini API로 전환했습니다. 이 과정에서 화면 문구, 응답 코드, 서버 로그 순서로 범위를 좁히는 방법을 배웠습니다.

## 10. 로컬과 배포 환경은 다르다

배포 과정에서 겪은 문제들입니다. Vercel이 requirements.txt를 보고 Python 프리셋을 자동으로 골랐는데, 우리 구조는 정적 화면과 함수가 나뉘어 있어서 Other로 바꿨습니다. 코드를 고쳐도 같은 오류가 나온 적이 있는데, 배포마다 붙는 고정 주소로 접속해서 예전 버전을 보고 있었습니다. 대표 주소를 쓰니 해결됐습니다. 환경 변수는 배포할 때 읽히기 때문에 값을 바꾼 뒤에는 꼭 재배포해야 했습니다. 또 Import를 두 번 해서 프로젝트가 두 개 생겼고, 키를 다른 프로젝트에 넣는 실수도 있었습니다. git push를 했는데 Everything up-to-date가 나왔을 때는 git status로 확인해 보니 파일이 실제로 바뀌지 않은 상태였습니다. 마지막으로 개발자 도구 필터 칸에 키를 붙여 넣은 채 스크린샷을 찍어서 키가 노출됐고, 바로 폐기하고 재발급했습니다. 정리하면, 배포에서만 생기는 문제는 지금 어떤 버전이 어떤 설정으로 돌고 있는지부터 확인해야 한다는 걸 배웠습니다.

## 11. 숫자마다 이유가 있다 (근거 없는 건 그렇다고 적었다)

코드에 들어간 숫자들의 이유입니다. 서버의 AI 호출 제한은 25초, 프론트는 30초로 서버를 더 짧게 했습니다. 서버가 먼저 끝나야 서버가 만든 정확한 안내 문구가 사용자에게 전달되기 때문입니다. 자동 재시도는 하지 않습니다. 실패할 때마다 다시 부르면 대기 시간과 사용량만 늘어나기 때문입니다. 8초 안내와 코스 2~3개는 이유는 있지만 숫자 자체는 실측 근거 없이 정한 값이라고 솔직하게 적었습니다. 만약 질문이 나오면, 실제 응답 시간을 측정해서 조정하는 게 다음 개선점이라고 답하겠습니다.

## 12. 지금 서비스가 못 하는 것

한계도 먼저 말씀드리겠습니다. 가장 큰 한계는 고속도로 제외가 보장되지 않는다는 점입니다. AI에게 지시만 할 뿐, 결과 경로를 실제로 검사하지는 않습니다. AI가 없는 장소를 만들 수도 있어서, 지금은 안내 문구와 네이버지도 링크로 사용자가 직접 확인하게 하는 것이 대응의 전부입니다. 거리와 시간도 AI 추정치입니다. 호출 횟수 제한이 없고, 결과 저장이나 날씨 연동도 없습니다. 다음에 개선한다면 지도 API로 경로를 검증하는 것을 가장 먼저 하고 싶습니다.

## 13. 이 프로젝트로 설명할 수 있게 된 것

과제 목표 여섯 가지에 대해 제 프로젝트에서 어떻게 해당되는지 정리했습니다. HTML은 구조, CSS는 모양과 반응형, 자바스크립트는 동작을 맡습니다. 입력값은 JSON으로 만들어 fetch로 서버 함수에 보내고, 응답을 카드로 그립니다. 서버리스 함수는 api 폴더의 파이썬 파일 하나가 그대로 주소가 되고, 요청이 올 때만 실행됩니다. 키를 환경 변수로 관리해야 하는 이유는 코드에 넣으면 GitHub와 브라우저를 통해 노출되기 때문인데, 저는 실제로 스크린샷으로 키가 노출돼서 폐기한 경험이 있어서 그 중요성을 체감했습니다. 로컬과 배포 환경의 차이, 그리고 오류 원인을 찾는 과정은 앞의 트러블슈팅에서 말씀드린 그대로입니다.

## 14. ridingnote.vercel.app

시연을 하겠습니다. 배포 주소에 들어가서 출발 지역에 서울 강동구, 하루, 와인딩, 중배기량으로 추천받기를 누릅니다. 결과가 나오는 동안 8초가 지나면 대기 안내가 바뀌는 것도 볼 수 있습니다. 결과가 나오면 경유지를 눌러 네이버지도가 열리는 것까지 보여 드리겠습니다. 이어서 출발 지역을 비우고 눌러서 빈 입력 안내도 보여 드리겠습니다. 시연 전에 배포 주소에서 실제로 추천이 성공하는지 미리 확인해 두세요. 들어 주셔서 감사합니다.
